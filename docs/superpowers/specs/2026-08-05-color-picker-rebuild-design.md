# Elens 颜色选择器内核重建设计

## 背景

Elens 当前使用原生 TypeScript 构建共享颜色选择器，服务于背景、边框、文字、阴影、SVG 填充与描边等多个 Inspector 编辑入口。现有弹层同时承担纯色、渐变、图片填充、颜色格式、透明度、吸管和页面颜色等功能，但交互状态与 DOM 渲染耦合，导致选色反馈不连续、文本输入丢焦点、页面颜色首次不出现，以及 `Libraries` 标签没有实际内容等问题。

本次工作选择完整功能范围：保留并修复纯色、渐变、多格式、透明度、吸管和页面颜色库，不进行无关的 Inspector 重构。

## 调研结论

调研了三个原生 Web 候选：

- Pickr：功能丰富且支持 Shadow DOM，但官方已冻结功能，核心为难维护的单体实现；不支持 Elens 所需的渐变断点编辑，并存在程序设色后视觉未同步的开放问题。
- Coloris：轻量、支持格式与色板，但使用全局单实例和大量 `document` 查询；完整 Shadow DOM 支持仍未合并，不适合嵌入式 Inspector。
- vanilla-colorful：TypeScript、Custom Element、Shadow DOM、键盘操作和状态模型都很适合作为内核参考，但不提供渐变、格式栏、吸管或页面颜色库，且现有鼠标/触摸切换实现仍有开放问题。

没有候选能够作为完整的直接替换。采用 Elens 原生外壳和新选色内核：参考 vanilla-colorful 的单一 HSVA 状态模型与组件边界，使用 Pointer Events 实现交互，不新增运行时依赖。

## 目标

- 拖动颜色平面、Hue 或 Alpha 时，目标元素、手柄、数值字段、色块和渐变预览在同一帧内保持一致。
- 支持纯色与当前活动渐变断点共用同一套选色内核。
- 保留 HEX、RGB、CSS、HSL、HSB 五种显示与编辑格式。
- 保留线性和径向渐变、断点增删、断点位置、透明度、交换方向和角度编辑。
- 保留 EyeDropper API 吸管能力，并明确呈现不支持状态。
- 让 `Custom` 与 `Libraries` 成为真实内容标签；`Libraries` 展示页面颜色。
- 保持现有 Elens 主题 token、Shadow DOM 隔离、浮层挂载和六位 HEX 规则。
- 对背景、边框、文字、阴影以及 SVG 填充和描边等现有调用方保持兼容。

## 非目标

- 不增加最近使用颜色、收藏、团队色板、设计 Token 导入或云端色库。
- 不增加新的颜色空间，如 OKLCH、LAB 或 Display-P3。
- 不修改 Inspector 之外的选区、工具栏、Changes 或扩展通信行为。
- 不重新设计整个弹层视觉风格。
- 不引入 Pickr、Coloris、vanilla-colorful 或其他运行时颜色选择器依赖。

## 架构

### 1. 颜色状态核心

新增独立的颜色状态模块，职责仅限于：

- 保存标准化的 HSVA 状态：`h` 为 0–360，`s`、`v`、`a` 为 0–1。
- 接收 HEX、RGB、HSL、HSB 和 CSS 输入并转换为 HSVA。
- 从 HSVA 生成六位 HEX、透明度百分比及各显示格式。
- 对所有通道进行边界限制和整数显示处理。
- 通过单一 `change` 回调输出完整状态，不直接操作 Inspector 样式或 DOM。

现有颜色转换函数优先复用；只有缺少稳定的双向转换或解析边界时才补充最小函数。

### 2. 交互控件

新增颜色平面控制器，管理颜色平面、Hue 和 Alpha 三个控件：

- 使用 Pointer Events 和 pointer capture 统一鼠标、触控板、触摸和笔输入。
- 颜色平面只修改 `s`、`v`；Hue 只修改 `h`；Alpha 只修改 `a`。
- 色彩平面右侧基色始终为当前 Hue 对应的 `hsl(h 100% 50%)`，不使用当前完整颜色作为基色。
- 支持方向键微调，Page Up/Down 大步调整，Home/End 跳到边界。
- 控件使用 `role="slider"`、`tabindex="0"`、`aria-valuemin/max/now/text`。
- 生命周期包含 `mount`、`setValue` 和 `destroy`，关闭或重绘弹层时必须清理全局监听和 pointer capture。

### 3. Elens 适配层

现有 `FillDraft` 仍是 Inspector 的业务状态。适配层负责在颜色核心与业务状态之间同步：

- 纯色模式：HSVA 写入 `draft.color` 和 `draft.opacity`。
- 渐变模式：HSVA 写入当前 `activeGradientStopId` 对应断点的 `color` 和 `opacity`。
- 每次状态改变后调用现有 `applySolid` 或 `applyGradient`，继续通过 `StyleTracker` 记录修改。
- 外部选择页面颜色或吸管颜色时，先更新核心状态，再由同一数据流更新业务状态和界面。

核心状态不直接保存渐变类型、角度、断点位置或图片填充数据。

## 渲染策略

当前实现频繁执行 `panel.innerHTML = ''`。新实现区分结构渲染与状态同步：

- 仅在切换 Custom/Libraries、纯色/渐变/图片模式、颜色格式、渐变类型或活动断点时重建相关结构。
- 拖动颜色控件、修改透明度或输入有效颜色时，只更新现有节点的值、位置、ARIA 属性、背景和预览。
- 文本输入期间不重建输入节点，避免丢失焦点、选区和输入法状态。
- HEX/CSS 文本允许用户保留尚未完成的草稿；仅在内容形成有效颜色时实时应用，Enter 或失焦时提交，无效内容恢复为最后有效值。
- 数字通道继续复用项目现有整数输入行为。

## 标签与页面颜色库

### Custom

显示当前已有的自定义编辑能力：

- 纯色、渐变和图片模式切换。
- 颜色平面、Hue、Alpha、吸管和格式字段。
- 渐变类型、断点、位置、颜色、透明度和角度。

### Libraries

显示页面颜色库：

- 页面颜色使用现有 `collectPageColors` 结果并去重。
- 第一次打开时若缓存尚未完成，显示轻量加载状态；收集完成后更新当前打开的 Libraries 内容。
- 页面没有可用颜色时显示明确空状态，不显示空白标签页。
- 点击颜色时，纯色模式更新填充颜色；渐变模式更新当前活动断点；透明度保持不变。
- 页面颜色缓存继续限频，避免每次打开同步扫描整个文档。

## 多格式编辑

- HEX：文本字段保持六位 HEX，不包含 `#`；透明度继续使用独立百分比字段。
- RGB：R、G、B 与透明度分别编辑。
- CSS：支持项目当前能够可靠解析的 `rgb()` 和 `rgba()`；无法可靠解析的值不提交。
- HSL：H、S、L 与透明度分别编辑。
- HSB：H、S、B 与透明度分别编辑，其中 B 对应 HSV 的 V。
- 切换格式只改变字段呈现，不改变实际颜色。

## 吸管行为

- 支持 `window.EyeDropper` 时，点击按钮打开系统吸管；成功结果进入统一 HSVA 数据流。
- 用户取消吸管时保持原颜色，不显示错误。
- 环境不支持时按钮显示禁用状态，并提供本地化的说明文本；不再静默无响应。
- 不自行实现屏幕截取或扩展权限升级。

## 错误与边界处理

- 无效文本输入不改变目标元素，失焦时恢复最后有效值。
- 颜色解析失败不得回退为黑色或白色，以免误导当前元素颜色。
- 透明或缺失背景继续保持透明语义，不显示为白色填充。
- 切换活动渐变断点时先完成当前字段提交，再加载新断点状态。
- 删除断点后保证至少保留两个断点，并选择仍存在的活动断点。
- 弹层关闭、目标元素变化或 Inspector 销毁时清理指针和文档监听器。
- 页面颜色异步结果只更新仍然存活且仍显示 Libraries 的弹层实例。

## 兼容性与样式

- 保持 `getFloatingLayerHost` 和 `event.composedPath()` 的 Shadow DOM 安全策略。
- 新控件使用现有 `.ei-dp-*` 命名、设计 token、输入框、按钮、标签和弹层样式。
- 只在现有 class 无法表达颜色平面状态时增加最少的新 class。
- 不导入第三方主题 CSS，不改变宿主页面全局样式。
- 现有调用方继续通过 `openSolidColorPopover`、`openFillPopover` 和 `FillDraft` 接口工作；必要的内部签名变化不暴露到公共 SDK API。

## 测试与验证

### 自动测试

- 颜色状态转换：HEX、RGB、HSL、HSB、透明度和边界值。
- Pointer 坐标到 HSVA 的映射，包括四角、中心和越界限制。
- 纯色拖动实时更新 `FillDraft` 和 `StyleTracker`。
- 渐变模式只更新活动断点，并实时更新渐变 CSS。
- 格式切换不改变颜色；有效输入提交，无效输入恢复。
- 页面颜色异步加载、空状态、选择颜色和弹层已销毁后的结果保护。
- EyeDropper 支持、取消与不支持状态。
- 销毁后不再响应 document 或 pointer 事件。

### 人工验收

由于 GUI 操作需要用户明确授权，默认只提供以下人工验收清单：

- 在 Web、扩展 Shadow DOM 和桌面入口分别打开颜色选择器。
- 连续拖动颜色平面、Hue 和 Alpha，确认字段、目标元素和预览实时同步。
- 逐项检查背景、边框、文字、阴影、SVG 填充与描边。
- 检查纯色和线性/径向渐变、断点增删与拖动。
- 检查五种格式输入和输入法编辑期间焦点不丢失。
- 检查 Custom/Libraries 切换、页面颜色首次加载和空状态。
- 检查吸管成功、取消和不支持环境。

## 风险与控制

- 共享组件回归：通过保持现有业务接口和覆盖所有调用方路径降低风险。
- 高频拖动性能：状态同步只更新现有节点和目标样式，不重建面板。
- Shadow DOM 事件泄漏：统一使用 pointer capture、`composedPath()` 和明确的 destroy 清理。
- 用户现有工作区改动：实现只触碰颜色选择器所需文件，并在编辑前重新检查相关差异。
- 旧版浏览器：沿用项目现代浏览器基线；不增加 ES5 兼容层。

## 验收标准

- 所有颜色入口共用新的选色核心且行为一致。
- 拖动过程中颜色和所有可见值实时同步，没有松手后才更新的延迟。
- HEX、RGB、CSS、HSL、HSB 均可查看和编辑，输入过程中不丢焦点。
- 纯色、透明度、吸管、线性/径向渐变和渐变断点可用。
- Libraries 标签真实展示页面颜色，首次打开能够加载并刷新。
- 不支持的吸管有明确状态，无静默失效。
- 类型检查、构建、设计系统检查、范围检查和相关测试通过；未执行的 GUI 验证被明确报告。
